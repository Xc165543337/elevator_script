## [1.4.1] — 2026-11-27

油猴脚本无变化；本次只修复 Python 版。

### Python 版

- 修复 `zipfile.BadZipFile: File is not a zip file`：后台求解在保存价值表时若进程被停止（Ctrl+C、本局结束），会在 `cache/` 留下写了一半的文件，
  下次启动读取时出错。现在先写临时文件再改名（原子保存）；读不出的缓存文件会被删除并重新求解
- 降低资源占用：numpy 的 BLAS 默认单线程（12 核笔记本上曾全部占满），后台求解线程用最低优先级；求解时价值表用 float32、
  用过的转移核即时释放，F4000 求解的内存峰值由 1.7 GB 降到 0.6 GB；求解进度显示进程内存。新增 `--solver light`
  （求解 104 秒而非 178 秒，实时决策少 2.5 倍模拟），适合性能较弱的电脑

## [1.4.0] — 2026-11-27

马尔可夫新增金币目标：同时刷物资与首领，划算时撤离带回背包。

### 新增

- 设置「马尔可夫目标」：首领数（默认）或**金币**——最大化带回的物资加上每个首领的金币价值（设置「每个首领值多少金币」，默认 100 万）。
  模型按地图的实测物资曲线计入找到的物资，死亡损失背包（安全箱约保住 20 万），撤离（层间、战斗中、首领战中）带回背包；
  通常在打不过的首领前撤离。两种目标的价值表分开缓存（Python 版 `--objective gold --gold-per-boss`）
- Python 版：每局记录带回的物资（runs.csv 的 banked 列），`offline.py` 汇总平均带回金币与每步金币，并按正式账号处理死亡
  （本地账号不再享受前 3 局的萌新防爆保险）

### 修复

- 彩虹物品全部集齐后不再停止：只要闪耀祝福还缺部件就继续正式下潜（配合「追寻祝福 → 自动」追寻缺件的套），全部集齐才停止
- 追寻的两套都已集齐而其他套还缺部件时，在日志中提示改用「自动」

### Python 版

- 同上：`farm.py` 在彩虹集齐后继续刷缺的闪耀祝福部件，并在追寻已集齐的套时提示 `--focus auto`

## [1.3.0] — 2026-11-27

设置里可直接选择追寻祝福，或自动追寻缺件最多的两套；马尔可夫换装后的重解更少。

### 新增

- 设置「追寻祝福」：正式下潜追寻的两套可沿用游戏内上次的选择（默认）、自动选缺件最多的两套（每次闪耀掉落是新部件的概率最高），
  或在面板里指定两套；每局开始时记录追寻的两套及新部件概率

### 变更

- 马尔可夫：求解用的 Build 吸附到 5% 网格（与 Python 版相同），相近的 Build 共用一次求解，换装后的重解更少

### Python 版

- `--focus auto`：每局自动追寻缺件最多的两套祝福，并记录闪耀掉落是新部件的概率
- 马尔可夫价值表：Build 吸附到 5% 网格后再查缓存，相近 Build 的各局共用缓存；后台线程求解（`--solve background`，默认），
  期间沿用旧表或阈值规则，不再暂停对局；`cache/` 只保留最近使用的 20 份
- 新增 `trial.py`：每周固定种子试炼「来自群星的寓言集」——在本地游戏引擎中搜索最深路线，再逐步核对状态在服务器上重放

## [1.2.1] — 2026-11-26

**仓库已公开，此版本起支持自动更新。** 与 Python 版重新对齐：阈值策略（对照测试的 254 个决策与全部战斗场景一致），并移植马尔可夫策略。

### 新增

- 设置「决策」可选**马尔可夫**（对应 Python 版 `--policy markov`）：整局求解的马尔可夫决策过程，回复药与烟雾弹按整局预算定价；
  包括精英整备、局内增益组合与手雷、对精英用烟雾弹、首领墙前撤离（预计还能击败的首领 < 0.3）、「为了我所期待的」
  （背包与安全箱物资不到 1500 万、回复后死亡率仍 ≥ 5% 时）。价值表在后台分片求解（约 5 分钟，内存峰值约 600 MB，之后约 350 MB），
  求解完成前用阈值规则。默认仍为阈值规则
- 历史记录与 CSV 记录本局使用的决策
- 连战自动打精英（设置「连战自动打精英」，默认开；Python 版 `--rush-elites`）：在同样安全时让连战自己打精英到整备，
  浅层不再每只精英都停下，每局请求更少。马尔可夫策略把它作为第三种走法求解，期望首领损失不超过 0.002 时采用；
  阈值策略要求含精英的连续 4 场战斗死亡率 ≤ 1%。只在需要时切换服务器设置
- 仓库已公开：从此版本起，在 Release 页面点击附件即可安装，油猴会自动检查更新（之前安装的版本没有更新地址，需按新方式重装一次）
- 遗物盒估值 ≥ 1000 万时舔包，放不进安全箱的部分仍 ≥ 1000 万时撤离带回；更便宜的捞尸换赏金
- 每局核对一次页面显示的遭遇概率，与模型不一致时提示
- 服务器重启（HTTP 502 等）时每分钟重试连接，最多 30 分钟

### 变更

- 战斗引擎与 Python 版一致：先取整再暴击、首回合加成与蓄力只作用于主攻、追击只在敌人存活时发生，并支持局内道具的防护 / 蓄力 / 闪避
- 闪耀祝福：缺刻值夜表两件后穿透上限 87%、四件「抢拍」（每 4 回合先手、承受 ×0.65）；深层破甲按本层数值削减敌防；校准识别抢拍回合
- 风隙羽标的逃跑加成计入 Build
- 肾上腺素因攻击加成上限被拒绝后本局不再尝试；缓释再生液还在生效时暂不再用
- 不含限层增益的 Build：临装未变时直接使用无增益时的属性（降低属性的增益不再被当成长期变化）

### Python 版

- 连战自动打精英（`--rush-elites on|off`，默认 on），规则同上
- `offline.py` 的正式局带上追寻祝福（`--focus`，默认 1,8）；此前因服务器要求追寻祝福而无法开局
- 马尔可夫策略遇到打不过的首领墙时撤离：预计还能击败的首领数（假设每个整备窗口都回满）低于 0.3 时撤离带回背包；打不赢的首领不再硬打，直接撤离或用烟雾弹脱出（同样算撤离）。背包里有替身娃娃时不撤离

## [1.2.0] — 2026-11-25

适配 2026-11-25 的服务器更新（精英整备、追寻祝福、闪耀祝福、遭遇概率调整）。**升级后建议先打一局练习确认。**

### 新增

- 正式下潜带上两套追寻祝福（沿用开局页上次选定的两套）；尚未选择时不开局并提示。进行中的正式局需要补选时自动补发
- 每局结束时记录新获得的闪耀祝福部件

### 变更

- 精英战按新规则估算：先估到第 8 回合整备，整备时重新决策（用药 / 继续），之后估到第 16 回合；普通怪按 15 回合上限估算（原来不设上限）
- 读取服务器的「打击减伤」二级属性
- 开局前把连战设为遇奇遇暂停、遇精英暂停（不自动打精英），与决策模型的假设一致
- 默认携带物资改为带满：7 种商店回复药与烟雾弹各 50 个（服务器单种上限），外加 2 支肾上腺素。保存的设置仍是旧默认值时自动换成新默认值；改过的保持不变
- 续玩进行中的对局时同样调整连战设置；服务器不允许时只记录提示，不中断

### Python 版（同一版本一起发布）

油猴脚本仍使用阈值策略；以下改动只在 Python 版（`farm.py`）中：

- 新增马尔可夫决策策略（`--policy markov`）：按楼层与有效生命逐层求解，回复药、烟雾弹按预算定价；精英整备、首领窗口、追寻祝福、闪耀祝福、深层破甲（缺刻值夜表等套装）均已建模
- 遗物盒估值 ≥ 1000 万时舔包，放不进安全箱的部分（≥ 1000 万）撤离带回；更便宜的捞尸换赏金
- 「为了我所期待的」只在用最好的回复后仍有 ≥ 5% 死亡风险时使用，且不会清掉 ≥ 1500 万的本局拾取
- 风隙羽标的逃跑加成、深层破甲公式、新版遭遇概率均已计入；服务器重启（HTTP 502）时等待重连

## [1.1.0] — 2026-11-25

同步 Python 版根据实战调整的决策规则与校准数据。**升级后建议先打一局练习确认。**

### 变更

- 回复手段（药品、手术匣、野外回复）全部用完时，在下一个安全时机撤离，带回背包
- 用尽回复与增益后，战斗死亡概率仍高于 10% 就撤离（原为 35%）；没有任何回复时，超过可接受风险即撤离
- 背包里捡到替身娃娃（死亡时保住背包）时不撤离，继续深入刷首领
- 判断能否连战时不计入限层增益（连战跨越多层，增益可能中途失效），改用最近一次无增益时的属性
- 只剩战地手术匣时，HP 低于 30% 才在遭遇中使用（原为 55%），简单战斗不再浪费手术匣
- 不再使用扩容袋：扩容袋珍贵，捡到的带回家
- 默认携带物资改为只带回复与肾上腺素：`adrenaline=2,ice_tea=50,coffee=50,triage_vial=50,slow_serum=50,barrier_serum=50,critical_serum=50,field_surgery=50`。保存的设置仍是旧默认值时自动换成新默认值；改过的保持不变
- 浏览器中尚无校准数据时，从 Python 版最新的校准系数起步

### 新增

- 「仓库去重」按钮：对仓库中的红 / 金物品执行「每种只留价值最高的一件」规则，其余出售；不开局，不出售其他稀有度（对应 Python 版 `--sell-now`）
