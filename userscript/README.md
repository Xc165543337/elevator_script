# 无尽电梯 · 自动刷首领（油猴脚本）

在 **无尽电梯** 网页版里自动刷首领，收集彩虹物品。决策逻辑与仓库根目录的 Python 版完全相同（有逐项对照测试），
区别是它直接运行在游戏页面上：

- **不需要账号密码**：先在游戏页面正常登录，脚本沿用这个会话。脚本不会读取、保存或发送密码
- **不需要安装 Python**，也不需要服务器：浏览器标签页开着就能刷
- 所有参数都在面板里设置，并保存在浏览器中

## 安装

1. 安装浏览器扩展 [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox 均可；
   Chrome 需在扩展详情中开启「允许用户脚本」）。
2. 打开本仓库最新 [Release](../../releases/latest)，点击附件 `elevator-farmer.user.js`，Tampermonkey 会弹出安装页 → 安装。
3. 打开游戏页面 `https://elevator.slime.icu/elevator/` 并登录，右下角会出现「无尽电梯 · 刷首领」面板。

**更新**：脚本带有更新地址（指向最新 Release 的附件），Tampermonkey 会定期自动检查；也可在管理面板中手动「检查更新」。
设置与记录保存在浏览器中，更新不受影响。1.2.1 之前的版本是在仓库私有时构建的，没有更新地址，需按上面第 2 步重装一次。

## 使用

| 按钮                    | 作用                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------- |
| 开始                    | 按设置连续打若干局；有进行中的对局时先继续那一局                                        |
| 本局后停止              | 打完当前这一局再停                                                                      |
| 立即暂停                | 当前请求返回后马上停下；对局保留在服务器上（**30 分钟无操作会过期**），再点「开始」继续 |
| 查看状态                | 显示图鉴进度、金币、门票与彩虹解锁情况                                                  |
| 仓库去重                | 出售仓库里重复的红 / 金物品，每种只留价值最高的一件（稀有度见设置）；不开局             |
| 导出记录 CSV / 导出轨迹 | 每局一行的历史记录；最近 500 步的决策与服务器结果（排查问题用）                         |

注意：

- 默认是**练习模式**（免费、无收益），先用它确认一切正常。切到「正式」后，开始前会弹窗确认要消耗的门票与金币
- 运行期间保持标签页打开，**不要同时在游戏界面里操作**（双方的操作会互相冲突）；结束后刷新页面即可看到最新状态
- 同一账号只能在一个标签页里运行脚本
- 标签页在后台时浏览器会放慢定时器，脚本已尽量避免依赖定时器，但前台运行最快

## 设置项

| 设置                | 默认                                    | 说明                                                                                    |
| ------------------- | --------------------------------------- | --------------------------------------------------------------------------------------- |
| 模式                | 练习                                    | 正式模式消耗门票，可能花费金币                                                          |
| 决策                | 阈值规则                                | 「马尔可夫」见下文                                                                      |
| 马尔可夫目标        | 首领数                                  | 金币：最大化带回的物资 + 每个首领的金币价值，划算时撤离带回背包                         |
| 每个首领值多少金币  | 1,000,000                               | 金币目标下，一个首领（闪耀 / 彩虹机会）相当于多少金币                                   |
| 局数                | 1                                       | 最多打几局；彩虹与闪耀祝福全部集齐、门票用完时提前停止                                  |
| 地图                | 废弃商场                                | 彩虹掉率各图相同，商场最容易打深；归潮档案只在潮汐发电站掉落                            |
| 追寻祝福            | 沿用游戏内上次的选择                    | 正式下潜追寻的两套：沿用、自动（缺件最多的两套，每次闪耀掉落的新部件最多）或指定两套    |
| 最高层              | 不限                                    | 到达即撤离                                                                              |
| 金币保留线          | 1,000,000                               | 补货与买票不会让金币低于此值                                                            |
| 携带物资            | 只带回复与肾上腺素（各 50，肾上腺素 2） | `物品id=数量`，逗号分隔；商店没有的物品会尝试在黑市制作；替身娃娃与扩容袋建议留在家里   |
| 开局前自动补货      | 开                                      | 补足携带物资                                                                            |
| 连战自动打精英      | 开                                      | 模型判断同样安全时，连战开启服务器的「自动打精英」，浅层不必每只精英都停下              |
| 购买付费门票        | 关                                      | 免费门票用完后每张 350 金币                                                             |
| 出售战利品          | 关                                      | 正式局结束后：整批出售本局新增的紫 / 绿 / 白材料与收藏品；红 / 金每种只留价值最高的一件 |
| 「伤害 ×2」临装评分 | -1                                      | 策划的平衡性调整（造成与承受伤害都 ×2）的评分；负数 = 不戴                              |
| 请求最短间隔        | 0.05 秒                                 | 服务器提示操作太快时会自动等待                                                          |
| 详细日志            | 关                                      | 记录每一步，而不只是重要事件                                                            |

### 决策：阈值规则与马尔可夫

两种决策与 Python 版的 `--policy threshold` / `--policy markov` 相同。

- **阈值规则**：手调的风险阈值（`policy.ts`），开箱即用
- **马尔可夫**：把整局（F1–F4000）当作马尔可夫决策过程求解，回复药与烟雾弹按整局预算定价，每一步选期望击败首领数最多的操作（`markov.ts`）。
  价值表在页面里分片求解（页面的安全策略不允许 Web Worker），**约 5 分钟，内存峰值约 600 MB，之后约 350 MB**，
  期间照常对局、用阈值规则。Build 明显变化（如换装）后在后台重解，期间继续用旧表（实时战斗始终按准确的 Build 模拟）。
  表只保存在内存中，刷新页面后重新求解

## 开发

需要 Node.js（`lts/*`），对照测试的数据由 Python 版生成（需要 numpy）。

```bash
npm install
npm run check        # 代码检查 + 格式检查 + 类型检查 + 单元测试与 Python 对照测试
npm run build        # 生成 dist/elevator-farmer.user.js
npm run parity       # 修改 Python 版后重新生成 tests/fixtures/parity.json
node scripts/preview-server.mjs   # 本地预览：模拟游戏页面与 API（不连接真实服务器）
```

| 文件            | 作用                                                                           |
| --------------- | ------------------------------------------------------------------------------ |
| `src/model.ts`  | 怪物成长公式与战斗蒙特卡洛（对应 `model.py`）                                  |
| `src/gear.ts`   | 装备 → 战斗属性（对应 `gear.py`）                                              |
| `src/combat.ts` | 局内战斗估算、连战风险、在线校准（对应 `combat.py`）                           |
| `src/policy.ts` | 决策：战斗 / 回血 / 增益 / 逃跑 / 撤离、奇遇、临装、安全箱（对应 `policy.py`） |
| `src/field.ts`  | 局内道具规格与对实时战斗的影响（对应 `field.py`）                              |
| `src/mdp.ts`    | 马尔可夫决策过程的价值表求解（对应 `mdp.py`）                                  |
| `src/markov.ts` | 由价值表驱动的决策（对应 `markov_policy.py`）                                  |
| `src/solver.ts` | 在页面主线程分片求解价值表，不阻塞对局                                         |
| `src/client.ts` | 同源 API 客户端（对应 `client.py`）                                            |
| `src/farmer.ts` | 运行器：门票、补货、开局 / 续局、记录（对应 `farm.py`）                        |
| `src/ui.ts`     | 悬浮面板（Shadow DOM，样式与游戏互不影响）                                     |

3. Release 工作流校验版本与更新日志、运行完整 CI，然后创建 Release 并附上 `elevator-farmer.user.js`
